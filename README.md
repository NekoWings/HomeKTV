# HomeKTV · B站局域网点歌

一个供家庭聚会试玩的最小版本：Windows / macOS 播放电脑运行房间服务，Chrome / Edge 扩展控制 B站原网页；朋友用电脑扩展或手机网页点歌。**当前是原型，聚会前请按文末清单在自己的浏览器试唱两首。**

## 可行性与取舍

- **视频来源可行**：使用 B站原视频页面和主机自己的登录状态，不下载、代理或重新分发视频。已在真实伴奏视频页面确认有标准 `video` 元素。
- **网页加按钮可行**：Chrome MV3 内容脚本在视频详情页提供悬浮点歌按钮，在搜索结果和推荐视频标题旁添加「＋点歌 / ↑置顶」。B站调整 DOM 后可能需要适配。
- **局域网同步可行，但需要一个服务端**：普通浏览器扩展不是通用局域网 HTTP 服务器。这里由主机运行零第三方依赖的 Node.js 服务；默认免口令，点歌端打开主机 IP 即可。暂不做自动发现或多房间。
- **顺序播放可行，但受网站和浏览器约束**：扩展创建一个专用播放标签页，通过 `play()`、`pause()`、`ended` 控制视频。切歌导航到下一首，关闭仅关闭专用标签页。有声自动播放首次可能需要手动点击；登录、风控、视频失效需要现场处理。
- **手机无需插件**：手机浏览器打开局域网点歌页，输入歌名 / 歌手搜索，一键点歌；备用入口可粘贴完整 B站视频 URL 或 BV号。暂不支持直接解析 `b23.tv` 分享短链接，需要先在浏览器打开短链接，再复制完整地址。

官方参考：[扩展内容脚本](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)、[扩展跨域请求](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)、[Chrome 自动播放策略](https://developer.chrome.com/blog/autoplay/)。

## 5分钟开房

### 1. KTV 电脑启动服务

需要 Node.js 20+。本项目无 npm 依赖，不需要 `npm install`。

Windows 可双击 `start.cmd`；macOS 在终端进入项目目录。两者都可运行：

```powershell
npm start
```

窗口会显示本机地址、局域网地址及是否启用口令。保持窗口运行；如果提示端口被占用，说明可能已经启动了一个实例，先打开本机网页检查。

- 本机通常是 `http://127.0.0.1:3210`。
- 手机要用 `http://192.168.x.x:3210` 一类的真实 Wi-Fi / 以太网地址，**不能用 127.0.0.1**。
- 多网卡时可能显示 VPN、WSL 虚拟网卡地址；选择和手机在同一个网段的地址。
- 如果 Windows 弹出防火墙提示，允许 Node.js 在家庭**专用网络**通信。不要做公网端口转发。

macOS 同样使用 Chrome / Edge 加载扩展，Safari 暂不支持；尚未在 Mac 实机验证。作为点歌端的 Mac 无需运行 Node 服务，只需连接现有主机。

### 2. 安装 Chrome / Edge 扩展

1. Chrome 地址栏打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
2. 开启「开发者模式」。
3. 选择「加载已解压的扩展程序」，选本项目下的 **extension 文件夹**（不是整个 HomeKTV 目录）。
4. 将 HomeKTV 图标固定到工具栏，点击图标打开控制台。
5. 主机服务地址填 `http://127.0.0.1:3210`，口令默认留空，保存并连接。允许扩展访问此服务地址。
6. 点击「接管播放」。保持这个控制台标签页打开。扩展每次重载、主机重启后需要重新接管。

另一个点歌电脑也可以安装相同的 `extension` 文件夹，地址填写 **KTV 电脑的局域网 IP**，默认无需口令；启用口令后各设备填写相同口令。它只要「保存并连接」，**不要接管播放**。

### 页面邀请二维码

页面会从服务端获取当前局域网地址，在本地生成邀请链接和二维码，每10秒刷新地址。从 localhost 打开也会显示可供手机使用的局域网 IP。多网卡时可选择与手机同网段的地址；没有可用地址时隐藏二维码并提示连接网络。二维码生成器 qrcode-generator 2.0.4（MIT）随项目提供，无需安装依赖或访问第三方二维码服务。

### 3. 点歌并试唱

- 电脑：打开 / 刷新 B站的视频页、搜索结果页，点击「＋加入歌单」或「↑下一首唱」。安装前已打开的 B站页面需要刷新。
- 手机：与主机连接同一 Wi-Fi，打开主机局域网地址即可点歌，名字可选。优先输入歌名 / 歌手搜索；「从视频链接添加」为备用入口。
- 第一首入队会成为当前歌曲，之后按顺序排队。「置顶」排到待唱列表第一位，不打断正在唱的歌。
- KTV 专用播放页第一次出现时，点击「开始唱 / 允许声音」。若有 B站登录提示，在该浏览器正常登录。
- 多P视频链接保留 `?p=2` 等参数：想唱哪一P，先在 B站选到那一P再点歌。简版以一个链接 / 分P为一首，不会把整个合集自动拆成歌单。
- 关闭 B站「自动连播」。建议播放器「网页全屏」配合浏览器 F11；浏览器原生视频全屏可能在跨页切歌时退出。每首导航后可能仍需重新进入网页全屏。

## 已实现

| 功能 | 行为 |
| --- | --- |
| 房间 | 同一服务默认免口令；所有房间成员都能控制歌单 |
| 加歌 / 置顶 / 移除 | 支持电脑扩展与手机网页，最多200首待唱 |
| 暂停 / 继续 | 作用于当前歌曲 |
| 切歌 / 自动下一首 | 旧歌曲事件和重复切歌不会误跳新歌曲 |
| 关闭播放页 | 保留当前歌曲和队列；重新播放从头开始 |
| 单一主机 | 心跳租约避免两台主机同时接管 |
| 状态同步 | 网页约1.5秒；主机约1秒，并接收服务器推送心跳 |
| 数据保存 | `data/room.json`；重启恢复当前曲目和队列，但暂停，等待手动继续 |
| 房间口令 | 默认关闭；通过 `KTV_ROOM_KEY` 环境变量可选启用。旧 `data/room-key.txt` 不再启用口令 |

控制台通过 HTTP 流心跳触发调度，避免只依赖隐藏标签页的定时器；控制台被关闭时扩展后台清理专用播放页。连接丢失时停止接管，需要重新点击接管。主机请保持供电，关闭系统睡眠；不要最小化后让节能模式冻结浏览器。

## 常见问题

- **手机打不开**：确认同 Wi-Fi、IP 正确、防火墙允许 TCP 3210；访客 Wi-Fi / AP隔离可能禁止设备互访。只连上 Wi-Fi 不代表局域网一定互通。
- **插件 Failed to fetch**：先在电脑浏览器直接打开服务地址；再检查扩展是否获准访问该地址。修改 IP 后要重新保存连接配置。若浏览器提示访问本地网络，请允许本次局域网连接。
- **提示主机已在线**：去原主机「停止接管」；原主机已关闭则等待约12秒再试。
- **有画面没声音 / 一直等待**：先在专用播放页点「开始唱」，检查系统和视频音量、登录、视频本身是否能正常播放；无效视频可手动切歌。
- **切歌后弹窗 / 自动跳出歌单**：确认已关闭 B站自动连播；刷新扩展和 B站页面后重新接管。页面结构变化可能需要修复插件。
- **需要换端口**：PowerShell `$env:PORT=3211` 后运行 `npm start`，各设备同步修改地址。

不包含：麦克风混音、降调、打分、消原唱、伴奏/原唱音轨切换、自动选画质、短链接展开、手机 B站 App 内按钮、跨公网房间。人声输入请用现有麦克风和音箱 / 混音设备；本工具负责点歌和视频播放。

## 验证与聚会前检查

```powershell
npm test
```

目前32项自动测试通过：歌单顺序、置顶、重复请求、并发操作、旧结束事件、主机互斥、恢复、免口令与可选口令鉴权、推送流，以及模拟视频的播放/暂停/结束/自动播放拦截。网页已在内置浏览器操作验证加入房间、点歌、排队和切歌，并检查390px窄屏。真实 B站页面已检查播放器 DOM。

**尚未完成：在实际 Chrome / Edge 加载本扩展后，真实 B站两首歌连续自动播放；真实手机跨设备局域网连接。模拟测试不等于这两项现场验证。**

聚会前建议花5分钟完成：

1. 主机加载扩展，加入房间并接管，手机连入点歌页。
2. 点两首短视频 / 伴奏，确认出声、手机暂停和继续生效。
3. 将第一首拖到接近末尾，确认结束后只推进一首。
4. 测试置顶、手动切歌和关闭播放页。
5. 断开主机控制台后确认播放页关闭，重新连接后可继续。

## 代码结构

```text
server.mjs          局域网 HTTP 服务、鉴权、状态保存、心跳流
lib/room.mjs        歌单状态机和主机租约
extension/          Chrome / Edge Manifest V3 扩展
web/                手机 / 电脑点歌网页

start.cmd           Windows 启动入口
```

## 可选口令

默认双击 `start.cmd` 或运行 `npm start` 即为免口令家庭模式，扫码直接进入歌单。
如需启用口令，在 PowerShell 中设置后启动（更改后需重启服务）：

```powershell
$env:KTV_ROOM_KEY = '你选择的口令'
npm start
```

恢复免口令：`Remove-Item Env:KTV_ROOM_KEY -ErrorAction SilentlyContinue`，再重启服务。启用口令时网页才要求输入；插件连接设置中的口令留空或填写对应口令。

## 手机搜索（0.2.0）

主机扩展更新后，在扩展管理页点「重新加载」，重新打开控制台，连接后点击「接管播放」。手机刷新页面即可看到搜歌框。

- 搜索模式可选 `KTV 伴奏`、日语 `ニコカラ` 或普通视频。
- 手机请求 → Node 搜索队列 → 主机扩展独立后台搜索标签页 → 读取公开可见的视频卡片 → Node → 手机列表。搜索不导航或关闭正在播放的标签页。
- 展示封面、标题、UP主、时长；支持「点歌」「下一首唱」和最多10页翻页，每页最多返回30个可识别视频。多分P视频点歌时弹出版本选择；当前曲目和待唱队列也可切换分P。
- 同关键词、模式和页码共享任务；缓存5分钟，最多5个未完成任务。插件读取超时约25秒，任务整体超时45秒。失败结果不会作为空搜索缓存。
- 搜索出错时，在主机控制台点击「查看搜索页」检查网络、登录或验证提示，再手动重搜。不会自动处理验证码，也不提取或上传 Cookie。
- 主机离线时可查看已有缓存；新搜索会提示先接管播放。暂不支持只启动 Node、不开浏览器就搜索。

验证：28项自动测试覆盖搜索排队、缓存、参数校验、超时、主机更换、结果过滤和完整 HTTP 任务传递；真实 B站搜索页已经确认可提取卡片字段。手机列表与一键点歌在隔离服务上使用实际卡片数据和模拟主机验证。实际 Chrome/Edge 装载新版插件后的全链路仍需现场试用。

### 0.2.1 搜索空白恢复

当 B站搜索框和排序栏已出现、但8秒仍没有视频列表时，插件会对专用搜索页执行一次普通刷新。不会抢占播放页，不会循环刷新。明确无结果或出现验证/访问限制提示时不会自动刷新。刷新后仍失败则保留25秒总超时和「查看搜索页」提示。

这是针对“手动刷新可恢复”现象的恢复措施，尚未确定 B站首次加载空白的根因。新增回归测试覆盖刷新后恢复、持续空白超时及验证/无结果不刷新的场景。

## 日语歌与版本选择（0.3.0）

- 搜索模式选择「日语 · ニコカラ」，输入歌名 / 歌手后自动加上 `ニコカラ`，并记住选择。
- 搜索结果点「点歌」或「下一首唱」时先读取 B站视频分P。单P直接点歌；多P弹出名称和时长供选择。超过5个分P可按歌名 / 版本筛选。
- Off Vocal 通常是伴奏，On Vocal 通常带人声；仅按上传者分P标题标注，不对音频做识别或消人声。
- 正在唱和待唱队列都有「版本 / 分P」按钮。当前歌曲切换版本会接续当前进度（需更新至 0.3.1 扩展，两个版本的时间轴需一致，加载期间可能短暂停顿）；暂停状态保留，队列顺序保留。旧版的结束事件不会误跳下一首。
- 分P信息由主机请求 B站视频信息接口，缓存5分钟；失败时提示重试，点歌可显式选择按原链接添加。不读取账号 Cookie。
- 本次仅网页和服务逻辑改变，现有 0.2.1 插件可以继续使用；更新服务后刷新网页、重新接管播放即可。

已用真实视频 `BV1ht411i7NH` 获取 On / Off Vocal 两个分P，并在隔离网页验证选择 P2、切回 P1。28项自动测试通过；真实播放页切换仍以现场浏览器效果为准。

## 接续进度切换（0.3.1）

更新后在 Chrome/Edge 扩展管理页重新加载 HomeKTV，关闭旧控制台再重新打开并接管。手机刷新页面即可。主机切换前暂停并读取实际进度，新分P加载后定位并恢复播放或暂停；目标较短时定位到结尾前。此版本尚未预加载另一个视频，不保证无缝；如果两个版本前奏不同，同一时间点也可能不是同一句歌词。关闭播放页后重新播放仍从头开始。

## 点歌按钮开关（0.3.2）

扩展控制台 → 浏览偏好 →「显示 B站点歌按钮」。默认开启，可随时关闭；设置保存在本浏览器，并立即同步到已打开且加载新版扩展的 B站页面。关闭会隐藏视频卡片旁按钮和普通视频页点歌浮窗，不影响专用播放页、手机点歌或搜索。更新扩展后请刷新已有 B站页面以加载新版脚本。
